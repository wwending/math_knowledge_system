# ADR 0002：超级管理员账号治理与用户名公开注册

日期：2026-08-31

## 决策

- 用户管理 HTTP API 仅允许 `super_admin`，普通 `admin` 继续保留其他既有管理员业务能力。
- 新账号以 NFC 规范化、大小写敏感的用户名作为登录标识；历史手机号继续可登录，且手机号与用户名共享冲突检查命名空间。
- 公开注册状态持久化在单行 `auth_settings` 中。迁移首次读取 `PUBLIC_SIGNUP_ENABLED`；新安装未配置时默认开启，迁移完成后环境变量不再覆盖数据库。
- 匿名注册只能创建启用的 `user`；超级管理员代创建只能直接选择 `user` 或 `admin`。
- 删除首次登录强制改密产品状态，兼容保留字段但所有设置入口写 `false`，迁移清除历史待改密状态。
- 匿名注册按可信客户端 IP 统计一小时成功数和十分钟失败数，配额计数使用数据库条件更新防止并发超额；成功注册和限流拒绝进入安全审计。
- 保留应用层最后一个超级管理员检查，并在当前 SQLite 持久化层增加更新触发器作为并发最终防线，避免两个治理请求同时移除全部活跃超级管理员。

## 原因与边界

用户名满足当前轻量账号需求，同时手机号兼容避免迁移历史账号。持久化开关保证多进程和重启后行为一致，并允许页面即时治理。可信代理模式只在部署明确声明 `trusted_proxy_tls` 且入口由防火墙限制到可信代理时采用转发地址；其他模式忽略客户端伪造的转发头。

不引入短信、邮件、验证码、邀请码、第三方风控或新生产依赖，不重写不符合新规则的历史账号。
